# MINE 1.0 dashboard foundation — DEMO ONLY

This independent React/TypeScript/Vite package is an explicitly authorized
architecture/UI foundation, **not an accepted product implementation** and not
part of the 0.2.0 executable. It does not alter the Root package, workflows,
execution graph, current Skills or backend. Never infer actual project status
from the illustrative identities or progress values displayed here.

## What works

- Switch between two local demo projects; derived summary counters update.
- Filter the work frontier and inspect a work item, its responsible role and
  the person who must answer a blocker.
- Inspect example decisions and handoffs. Unimplemented actions explicitly
  explain that there is no backend; they never report a successful mutation.
- Autonomous mode is visibly off. There are no session creation, messaging,
  approval, provider credentials or network API calls in this shell.

`src/model.ts` is a view mapping, not the durable schema. The MINE example
consumes `../contracts/fixtures/frontier.json` through an Ajv 2020 validator
compiled from the shared Rust-produced `../contracts/schema.json`.
`src/generated/contracts.d.ts` is generated by pinned
`json-schema-to-typescript`, never separately handwritten. Build/typecheck/test
refuse schema/type drift. Unknown fields, unknown states, malformed UUIDs,
noncanonical counters and signed64 cursor overflow are refused without coercion;
the signed64 semantic check uses BigInt rather than imprecise Number conversion.
Local short-ID profiles/progress are explicitly illustrative decorations; the
wire IDs, project identity, cursor, pause flag, work state and waiting principal
come from the shared fixture. Runnable work is not reported as reviewed.

Server authentication, session control, real event
streaming, accessibility acceptance and end-to-end tests remain future work.

## Exact requested preset

The source `components.json`, `src/index.css`, `src/components/ui/button.tsx`
and `src/lib/utils.ts` were generated by the real **shadcn 4.21.5** CLI:

```text
shadcn init --template vite --preset b2jI --name preset-source --cwd <Root>/.mine/build/v1-foundation/ui/shadcn-generator --no-monorepo --yes
```

The command completed with exit 0. These generated files were copied without
theme approximation into this package. Preset URL:
<https://ui.shadcn.com/create?preset=b2jI>.

`index.css` has one terminal LF added by the repository patch writer; its
generated content and theme declarations are otherwise unchanged. The other
three generated files match the generator's bytes.

Decoded configuration: version `b`, Base UI, `base-nova`, neutral base/theme/
chart colors, Lucide icons, Geist font, inherited heading font, large radius
(`0.875rem`), subtle menu accent and default menu color. Font assets are served
from pinned `@fontsource-variable/geist`; there is no runtime font CDN.
Application layout CSS is separate from the generated preset.

## Root-owned tools and outputs

Run from this package with Node 24 and npm. First serialize setup (no other
dashboard command may be using the environment):

```text
npm run prepare-env
npm run check-contract
npm run typecheck
npm test
npm run build
npm run dev
```

The development server binds **127.0.0.1:4178**, not an external interface.
The runner resolves the repository Root through Git's common directory and
keeps dependencies and every mutable output under:

```text
<Root>/.mine/build/v1-foundation/ui/environment/node_modules
<Root>/.mine/build/v1-foundation/ui/vite-cache
<Root>/.mine/build/v1-foundation/ui/dist
```

Do not run a normal `npm install` inside this directory: it would create a
second dependency tree. Refresh the lockfile only with the owning maintainer's
serialized `npm install --package-lock-only --ignore-scripts`; then prepare the
Root environment. Source and environment manifest/lock bytes must match before
build or typecheck. This foundation has one output owner; parallel future Plans
must use their own node-specific mutable output roots, not share this directory.

The runner verifies Root against Git common-directory and checkout identity.
In a registered linked worktree, set exact `MINE_PLAN_ID`; the installed native
`mine plan show --id <id> --format json` must match active/reviewable status,
registered branch and the actual checkout real path. Outputs then go to
`<Root>/.mine/build/<exact-plan-id>/ui/`, while dependencies stay shared read-only.
Compensation nodes use their own output ID, not their shared lineage ID.
Missing/mismatched identities refuse rather than guessing an ancestor folder.
Only Root may run `prepare-env`; a linked checkout cannot reinstall dependencies.
Nonstandard separate-Git-directory repositories are explicitly unsupported.

After the shared contract owner regenerates `schema.json`, the UI owner runs
`npm run generate-contract`, then the normal check/test/build matrix. Do not
edit generated types or copy a second schema into this package.

The package and lockfile are independent. It is not registered in the Root npm
or Cargo manifests and adds no CI requirement. Being in `v1/` does **not** by
itself exclude tracked files from source snapshots, scanning, packaging or
whole-tree evidence: the release owner must preserve the explicit 0.2.0
curation boundary. No release acceptance is claimed by a successful local build.
